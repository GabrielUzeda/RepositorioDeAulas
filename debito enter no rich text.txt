## DT-01: Hover do Botão "Vincular" no Dark Mode e Inconsistência de Tokens

### 1.1 Diagnóstico do Problema e Causa Raiz
No arquivo `frontend/src/professor/ProfessorView.vue`, o botão de vincular atividades existentes a uma aula utiliza o componente `BaseButton` com `variant="ghost"`, recebendo classes adicionais:
```html
<BaseButton
  variant="ghost"
  size="xs"
  @click="handleOpenVincularModal(aula)"
  title="Vincular atividades existentes a esta aula"
  class="mr-1 text-secondary hover:text-primary"
>
```
Foram identificadas duas causas raízes conjuntas:
1. **Token CSS do Dark Mode quebrado**: Em `frontend/src/shared/style.css`, na linha 102 (bloco `.dark`), a variável CSS `--c-accent-light` está configurada com `#dbeafe` (o mesmo azul claro pastel do modo claro!). Em um fundo escuro `#0f172a`, o hover com fundo `#dbeafe` produz um brilho ofuscante e alto ruído visual.
2. **Conflito de especificidade Tailwind**: `BaseButton.vue` na variante `ghost` aplica `hover:bg-accent-light hover:text-accent`. No `ProfessorView.vue`, a classe passada `hover:text-primary` entra em conflito de sobreposição com `hover:text-accent`, deixando o estado de hover inconsistente.

### 1.2 Impacto
- **Usuário afetado:** Professores utilizando a interface no modo noturno.
- **Sintoma:** O botão pisca um retângulo branco-azulado de alto contraste ao passar o mouse, quebrando a harmonia do tema e tornando o ícone/texto ilegíveis momentaneamente.

### 1.3 Fluxo do Usuário
```
[Professor ativa Dark Mode] ──► [Acessa Disciplina] ──► [Expande Aula] ──► [Hover em 'Vincular']
                                                                                   │
                                                                                   ▼
                                                                  [BUG: Fundo ofuscante #dbeafe]
```

### 1.4 Arquivos Afetados
- `frontend/src/shared/style.css` (Definição da variável `--c-accent-light` em `.dark`)
- `frontend/src/shared/components/BaseButton.vue` (Definição de variantes e classes de hover no variant `ghost`)
- `frontend/src/professor/ProfessorView.vue` (Remoção de classes conflitantes `text-secondary hover:text-primary`)

### 1.5 Solução Técnica Proposta
1. Ajustar o token no `frontend/src/shared/style.css` em `.dark`:
   ```css
   .dark {
     /* Substituir #dbeafe por cor escura suave com transparência ou tom marinho */
     --c-accent-light: rgba(59, 130, 246, 0.15); /* ou #1e293b / #172554 */
   }
   ```
2. Padronizar `BaseButton.vue` para variante `ghost` usando `hover:bg-surface-alt` ou `hover:bg-accent/15`.
3. Limpar classes conflitantes no botão do `ProfessorView.vue`.

## DT-02: Rótulo do Botão de Avaliação ("Ver Respostas dos Alunos" → "Respostas")

### 2.1 Diagnóstico do Problema
Nos cards de atividade em `frontend/src/professor/ProfessorView.vue` (linhas 922 e 1077), o botão de acesso ao modal de avaliação utiliza o texto por extenso:
```html
<BaseButton variant="secondary" size="sm" @click="handleOpenRespostasModal(atv)">
  <span class="material-icons text-sm">analytics</span>
  <span>Ver Respostas dos Alunos</span>
</BaseButton>
```
Com 24 caracteres, o botão ocupa um espaço excessivo na barra de ações dos cards pedagógicos, forçando quebra de linha em telas com resolução intermediária (laptops de 13", tablets e modo janela dividida) e poluindo visualmente a lista de atividades.

### 2.2 Impacto
- **Usuário afetado:** Professor visualizando listas longas de atividades gerais ou vinculadas a aulas.
- **Sintoma:** Barra de ferramentas do card quebra em duas linhas desnecessariamente; rótulo verboso e redundante em relação ao ícone `analytics`.
- **Risco colateral crítico:** O teste E2E `e2e/tests/fluxo-completo.spec.ts` (linha 180) busca explicitamente pelo texto completo:
  ```ts
  await page.getByRole('button', { name: 'Ver Respostas dos Alunos' }).click();
  ```
  Se a alteração for feita no frontend sem atualizar a suíte de testes e o `AGENTS.md`, a suite de testes E2E falhará.

### 2.3 Fluxo do Usuário
```
[Professor no Painel] ──► [Card da Atividade] ──► [Botão 'Respostas' compacto] ──► [RespostasModal]
```

### 2.4 Arquivos Afetados
- `frontend/src/professor/ProfessorView.vue` (Linhas 922 e 1077 — alteração do texto do botão para `Respostas`)
- `e2e/tests/fluxo-completo.spec.ts` (Linha 180 — ajuste do seletor do Playwright para `name: /Respostas/i`)
- `AGENTS.md` (Linhas 195 e 272 — atualização da documentação de seletores e jornada)

### 2.5 Solução Técnica Proposta
1. Atualizar o template do botão em `ProfessorView.vue`:
   ```html
   <BaseButton variant="secondary" size="sm" @click="handleOpenRespostasModal(atv)">
     <span class="material-icons text-sm">analytics</span>
     <span>Respostas</span>
   </BaseButton>
   ```
2. Atualizar o seletor no teste Playwright `fluxo-completo.spec.ts`:
   ```ts
   await page.getByRole('button', { name: /Respostas/i }).click();
   ```
3. Refletir a atualização nas referências de `AGENTS.md`.

## DT-03: Contexto de Questões Preexistentes no Gerador de Atividades por IA

### 3.1 Diagnóstico do Problema
O modal `frontend/src/professor/components/JsonActivityEditorModal.vue` possui o gerador de questões por IA integrado. No entanto, quando o professor já possui questões cadastradas na atividade (por exemplo, 3 questões manuais ou de uma rodada anterior de IA) e clica em "Gerar e Adicionar Questões na Atividade":
1. O frontend despacha `POST /ai/generate-activity` enviando apenas:
   ```json
   {
     "tipo": "normal",
     "titulo": "...",
     "tema": "...",
     "observacoes": "...",
     "quantidade": 5,
     "disciplina_id": 1,
     "aulas_ids": [1]
   }
   ```
2. O array reativo `questions.value` do editor **não é enviado** para a API.
3. O backend em `backend/src/ai.ts` constrói o prompt para o modelo de IA sem qualquer conhecimento das perguntas que já constam na atividade.
4. Consequentemente, o modelo gera perguntas que repetem conceitos, enunciados ou objetivos de aprendizagem já cobertos nas questões anteriores.

### 3.2 Impacto
- **Usuário afetado:** Professor montando uma lista avaliativa incremental.
- **Sintoma:** Retrabalho constante de ter que apagar questões duplicadas ou reformular manualmente os enunciados repetidos pela IA.

### 3.3 Fluxo Arquitetural
```
[Professor tem 3 questões no Editor]
         │
         ▼
[Clica em 'Gerar e Adicionar Questões']
         │
         ├──► Frontend extrai resumo de `questions.value`: [{ title, content }]
         │
         ▼
[POST /ai/generate-activity] (com payload: { questoes_existentes: [...] })
         │
         ▼
[Backend: ai.ts injeta no Prompt de Sistema / Usuário]
         │ "QUESTÕES JÁ EXISTENTES NESTA ATIVIDADE (NÃO REPETIR Nem abordar os mesmos tópicos/perguntas):"
         │ "- Questão: [Título] - [Enunciado]"
         │
         ▼
[LLM gera questões inéditas e complementares]
         │
         ▼
[Frontend anexa as novas perguntas ao final de `questions.value`]
```

### 3.4 Arquivos Afetados
- `frontend/src/professor/components/JsonActivityEditorModal.vue` (Inclusão de `questoes_existentes` no payload de `handleGenerateAiQuestions`)
- `backend/src/ai.ts` (Recepção de `questoes_existentes`, montagem do contexto no `userPrompt` e instrução de unicidade)
- `backend/src/ai.test.ts` (Validação de que `questoes_existentes` é processado sem quebrar o schema)

### 3.5 Solução Técnica Proposta
1. No `JsonActivityEditorModal.vue`, enviar no payload:
   ```ts
   questoes_existentes: questions.value.map(q => ({
     title: q.title,
     content: q.content.slice(0, 300)
   }))
   ```
2. No `backend/src/ai.ts`:
   - Receber `questoes_existentes = []` do corpo da requisição.
   - Adicionar ao `userPrompt`:
     ```ts
     if (questoes_existentes.length > 0) {
       userPrompt += `\nQUESTÕES JÁ EXISTENTES NESTA ATIVIDADE (É EXPRESSAMENTE PROIBIDO REPETIR ESTES ENUNCIADOS OU CONCEITOS):\n`;
       questoes_existentes.forEach((q: any, i: number) => {
         userPrompt += `${i + 1}. [${q.title}] ${q.content}\n`;
       });
       userPrompt += `\nGere ${quantidade} novas questões INÉDITAS, que complementem o aprendizado sem sobrepor o que já foi perguntado acima.\n`;
     }
     ```

## DT-04: Nomenclatura Pedagógica dos Títulos de Questões Geradas por IA

### 4.1 Diagnóstico do Problema
No backend `backend/src/ai.ts`, as definições de template de retorno JSON instruem explicitamente:
```json
"questions": [
  {
    "title": "Questão 1",
    "content": "Enunciado claro e detalhado..."
  }
]
```
Além disso, o `systemPrompt` não contém nenhuma diretriz sobre o campo `title`. Modelos de linguagem seguem os exemplos literais de esquemas JSON (few-shot learning). Como resultado, 100% das questões geradas recebem como título `"Questão 1"`, `"Questão 2"`, `"Questão 3"`.
Na visualização do aluno (`ActivityModal.vue`), a interface já renderiza o índice numérico (`1.`, `2.`). Ter o título como `"Questão 1"` gera a redundância visual `"1. Questão 1"`, em vez de apresentar o tema ou competência pedagógica (ex.: `"1. Condicionais Compostas (if/else)"` ou `"2. Complexidade de Algoritmos"`).

### 4.2 Impacto
- **Usuário afetado:** Professores (ao gerenciar a atividade) e Alunos (ao resolver a atividade e revisar o feedback).
- **Sintoma:** Falta de clareza temática; perda do propósito do campo `title` como identificador de conteúdo.

### 4.3 Arquivos Afetados
- `backend/src/ai.ts` (Templates JSON e regras de diretrizes do `systemPrompt`)
- `backend/src/ai.test.ts` (Testes de integração das chamadas de IA)

### 4.4 Solução Técnica Proposta
1. Atualizar o `systemPrompt` em `backend/src/ai.ts`:
   ```ts
   DIRETRIZES FUNDAMENTAIS:
   ...
   7. DIRETRIZ OBRIGATÓRIA DE NOMENCLATURA: O campo "title" de cada questão DEVE conter o TEMA ou CONCEITO ESPECÍFICO avaliado (ex: "Declaração de Variáveis e Tipagem", "Recursão e Pilha de Chamadas", "Tratamento de Exceções em Python"). NUNCA use "Questão 1", "Questão 2", "Pergunta 1" ou títulos genéricos vazios.
   ```
2. Alterar os exemplos no `formatoJson`:
   ```json
   "questions": [
     {
       "title": "Conceito Central / Tópico Abordado",
       "content": "Enunciado claro e detalhado..."
     }
   ]
   ```

## DT-05: Ciclo de Vida e Status de Entidades (Ativo, Oculto, Arquivado)

### 5.1 Diagnóstico do Problema
Atualmente, as tabelas `cursos`, `disciplinas` e `atividades` no SQLite (`backend/src/db.ts`) não possuem coluna de estado ou status:
- Não há como um professor arquivar uma disciplina encerrada de um semestre letivo anterior sem apagá-la.
- Se o professor excluir a disciplina para tirá-la da tela, um efeito cascata (`ON DELETE CASCADE`) apaga todas as aulas, atividades, respostas de alunos, notas e feedbacks da turma.
- Não há como preparar uma atividade em modo "Rascunho / Oculta" sem que ela fique imediatamente visível para todos os alunos na tela pública (`AlunoView.vue`).

### 5.2 Estrutura de Estados Proposta
```
 ┌──────────┐      ocultar       ┌──────────┐
 │  ATIVO   │ ─────────────────► │  OCULTO  │
 └────┬─────┘                    └────┬─────┘
      │                               │
      │ arquivar                      │ arquivar
      ▼                               ▼
 ┌──────────────────────────────────────────┐
 │                ARQUIVADO                 │
 └──────────────────────────────────────────┘
```

- **`ativo` (padrão)**: Visível para professores, administradores e alunos.
- **`oculto`**: Visível apenas para professores e administradores (útil para elaboração de atividades antes da data da aula ou disciplinas em planejamento).
- **`arquivado`**: Modo somente leitura histórico. Visível apenas no painel administrativo/professor em aba dedicada ou filtro ("Arquivados"). Oculto para alunos.

### 5.3 Arquivos Afetados
- `backend/src/db.ts` (Adição da coluna `status TEXT DEFAULT 'ativo'` nas tabelas `cursos`, `disciplinas` e `atividades`, com migração segura via `ALTER TABLE ... ADD COLUMN` para bancos legados)
- `backend/src/routes.ts`:
  - `GET /cursos`: Alunos recebem apenas `WHERE status = 'ativo'`; Professores/Admin recebem todos ou podem filtrar via `?status=`.
  - `GET /cursos/:id/disciplinas`: Alunos recebem apenas disciplinas com `status = 'ativo'`.
  - `GET /disciplinas/:id/atividades`: Alunos recebem apenas atividades com `status = 'ativo'`.
  - Endpoints rápidos de atualização: `PATCH /cursos/:id/status`, `PATCH /disciplinas/:id/status`, `PATCH /atividades/:id/status`.
- `frontend/src/shared/types/index.ts` (Adição da propriedade opcional `status?: 'ativo' | 'oculto' | 'arquivado'` nos tipos `Curso`, `Disciplina` e `Atividade`)
- `frontend/src/admin/AdminView.vue` (Exibição de badge de status e ação de arquivar cursos)
- `frontend/src/professor/ProfessorView.vue` (Filtros de abas "Todas", "Ativas", "Arquivadas" e toggle de status rápido nos cards)
- `frontend/src/aluno/AlunoView.vue` (Consumo estrito de conteúdos ativos)

### 5.4 Script de Migração Retrocompatível (`backend/src/db.ts`)
```sql
-- Executar em bloco de inicialização caso a coluna ainda não exista
ALTER TABLE cursos ADD COLUMN status TEXT DEFAULT 'ativo';
ALTER TABLE disciplinas ADD COLUMN status TEXT DEFAULT 'ativo';
ALTER TABLE atividades ADD COLUMN status TEXT DEFAULT 'ativo';
```

## DT-06: Quebras de Linha, Enter e Indentação no RichText e na Visualização do Aluno

### 6.1 Diagnóstico do Problema e Causas Raízes
A renderização e edição de conteúdos com múltiplas linhas, quebras de parágrafo (Enter) e indentação (espaços e tabulações) sofrem de quatro gargalos em diferentes pontos do sistema:

#### Gargalo A: Colapso de Indentação pelo `whitespace-pre-line` (`ActivityModal.vue`)
Em `frontend/src/aluno/components/ActivityModal.vue` (linhas 367 e 403), o enunciado é renderizado da seguinte forma:
```html
<p class="text-sm text-secondary whitespace-pre-line leading-relaxed bg-surface-alt/50 p-3 rounded-lg border border-line">
  {{ q.content }}
</p>
```
**Causa:** Pela especificação CSS, a regra `whitespace-pre-line` preserva quebras de linha (`\n`), mas **colapsa sequências de espaços e tabulações em um único espaço**. Se o professor cadastrar código indentado, exemplos em tópicos ou tabelas de texto:
```python
def soma(a, b):
    return a + b
```
O CSS colapsa a indentação de 4 espaços para apenas 1 espaço:
```python
def soma(a, b):
 return a + b
```

#### Gargalo B: Ausência total de preservação de quebras em Reforço e Roleta
Nos modais `ReforcoModal.vue` (linha 169) e `RoletaModal.vue` (linha 235), o enunciado é exibido sem qualquer classe de whitespace:
```html
<p class="text-primary text-base font-medium leading-relaxed">{{ currentQuestion.content }}</p>
```
Todas as quebras de linha (`\n`) são tratadas como um espaço simples pelo navegador, desformatando enunciados com múltiplos parágrafos.

#### Gargalo C: Teclas Enter e Tab no `RichTextEditor.vue`
No componente de resposta do aluno `frontend/src/shared/components/RichTextEditor.vue`:
1. **Quebra dentro de blocos de código (`<pre><code>`)**: Quando o aluno usa a ferramenta de bloco de código e pressiona `Enter`, o comando contenteditable do navegador tenta dividir a tag `<pre>` em dois blocos de código separados, em vez de inserir uma quebra de linha `\n` dentro do código existente.
2. **Perda de foco na tecla `Tab`**: Ao pressionar `Tab` para identar seu código ou resposta, o navegador dispara o evento nativo de navegação de acessibilidade, tirando o foco do editor e selecionando o próximo elemento interativo da página.
3. **Colapso de parágrafos vazios**: O navegador insere `<p><br></p>` ao teclar `Enter`. Ao salvar e sanitizar, se o `<p>` não tiver altura mínima garantida por CSS, linhas em branco sucessivas são colapsadas visualmente.

#### Gargalo D: Ausência de estilização de parágrafos no `RespostasModal.vue`
No painel do professor (`frontend/src/professor/components/RespostasModal.vue`, linha 394), as respostas submetidas pelos alunos são renderizadas via `v-html="sanitizeRichText(item.value)"`. O container define classes para `[&_h2]`, `[&_pre]`, `[&_ul]`, mas **não define margens para parágrafos (`[&_p]`)**:
```html
<div
  class="px-4 py-3 bg-surface text-sm text-primary leading-relaxed ... max-w-none"
  v-html="sanitizeRichText(item.value)"
></div>
```
Como o Tailwind Preflight zera as margens de tags `<p>` (`margin: 0`), parágrafos separados com `Enter` pelo aluno são exibidos colados verticalmente sem espaçamento perceptível.

### 6.2 Impacto
- **Usuário afetado:** Alunos resolvendo avaliações discursivas ou técnicas, e Professores corrigindo as respostas.
- **Sintoma:** Códigos ilegíveis sem indentação, enunciados condensados sem espaçamento entre parágrafos, e respostas discursivas difíceis de ler.

### 6.3 Fluxo de Dados e Renderização
```
[Professor digita Enunciado / Código com quebras e indentações]
                           │
                           ▼
              [Salvo no SQLite em json_data]
                           │
                           ▼
          ┌────────────────┴────────────────┐
          ▼                                 ▼
   [AlunoView / Modal]              [RichTextEditor]
          │                                 │
  Muda de `pre-line`                Intercepta:
  para `pre-wrap`                   - Enter em <pre> (insere \n)
  + `tab-size: 4`                   - Tab (insere 2 espaços ou \t)
  + fonte mono se código            - Garante altura em <p><br></p>
          │                                 │
          ▼                                 ▼
[Visualização Fiel]               [Resposta Estruturada]
                                            │
                                            ▼
                                   [RespostasModal (Prof)]
                                            │
                                  Aplica regras `prose` ou
                                  `[&_p]:mb-3 leading-relaxed`
```

### 6.4 Arquivos Afetados
- `frontend/src/aluno/components/ActivityModal.vue` (Substituição de `whitespace-pre-line` por `whitespace-pre-wrap` com `style="tab-size: 4;"`)
- `frontend/src/aluno/components/ReforcoModal.vue` (Adição de `whitespace-pre-wrap`)
- `frontend/src/aluno/components/RoletaModal.vue` (Adição de `whitespace-pre-wrap`)
- `frontend/src/shared/components/RichTextEditor.vue`:
  - `keydown.enter`: Tratar quebra dentro de tags `<pre><code>`.
  - `keydown.tab`: Prevenir perda de foco e inserir indentação configurável (2 espaços).
  - CSS: Garantir espaçamento e altura mínima para tags `<p>` vazias com `<br>`.
- `frontend/src/professor/components/RespostasModal.vue`:
  - Adição de classes de espaçamento de parágrafos (`[&_p]:mb-2.5`, `[&_p:last-child]:mb-0`).
  - Tratamento de respostas antigas em texto puro convertendo quebras de linha (`\n`) em `<br>`.

## Cronograma de Implementação Recomendado

A execução deve seguir uma ordem lógica para isolar regressões e garantir testes verdes a cada etapa:

1. **Fase 1: Correções Rápidas de UI e CSS (DT-01 e DT-02)**
   - Corrigir `--c-accent-light` em `.dark` no `style.css`.
   - Limpar classes conflitantes no botão Vincular do `ProfessorView.vue`.
   - Renomear o botão para "Respostas" e atualizar `fluxo-completo.spec.ts` e `AGENTS.md`.

2. **Fase 2: Motor de Edição e Renderização de Texto (DT-06)**
   - Aplicar `whitespace-pre-wrap` e suporte a indentação nos modais do aluno (`ActivityModal`, `ReforcoModal`, `RoletaModal`).
   - Melhorar `RichTextEditor.vue` com interceptação de `Enter` em `<pre>` e suporte à tecla `Tab`.
   - Ajustar a folha de estilo de renderização de respostas em `RespostasModal.vue`.

3. **Fase 3: Inteligência Artificial e Prompts (DT-03 e DT-04)**
